APIs

Rate limits added this pass

  • checkout/payment-session — 10/60 s
  • checkout/gift — 20/60 s
  • partner-applications — 3/3600 s
  • shipping/rates — 30/60 s (each call costs a Shiprocket request)
  • tax/calculate — 60/60 s

Still open by design

  • /currency, /notifications/read — cheap, session-scoped
  • /webhooks/razorpay, /webhooks/ses — signature-verified, so limiting them would only drop real events
  • /webhooks/courier — shared-secret header, neutral path (Shiprocket bans shiprocket in webhook URLs)

Scanner: 153 routes (129 storefront, 24 backend). Every route touching money, stock or a customer record is behind a session or secret guard. The "no recognisable guard" list is now only login, password reset, newsletter, cart count and the public catalogue — all rate-limited or read-only.

DNS and email authentication

The domain is on Cloudflare and live. What is missing is the part that decides whether order confirmations reach an inbox:

RecordCurrentStatus
resend._domainkey (DKIM)Present, so mail from no-reply@snehavrinda.in is signed and aligned.OK

_dmarcNo record at all. Gmail and Yahoo expect one from any sender, and without it spoofed mail using the studio's name is judged the same as real mail.Missing

Three records to add in Cloudflare (all DNS-only, no orange cloud): send MX 10 → feedback-smtp.us-east-1.amazonses.com; send TXT → v=spf1 include:amazonses.com ~all; _dmarc TXT → v=DMARC1; p=none; rua=mailto:hello@snehavrinda.in. Start at p=none, read the reports for two weeks, then move to quarantine.
