# sitemap.xml

This file is a **snapshot**, kept so the shape of the sitemap can be reviewed
without a running server. It is not what Google should be given.

The real sitemap is generated by `apps/storefront/app/sitemap.ts` and served at:

```
https://snehavrinda.in/sitemap.xml
```

It is rebuilt on every request from the live catalogue, so a work published this
morning appears in it this morning and a work unpublished disappears. Submitting
the URL rather than uploading this file is the difference between a sitemap that
stays true and one that is already out of date.

## What it contains (snapshot taken 2026-11-27)

- 136 URLs in total, 68 of them Hindi
- every published work (`/products/…`), category (`/shop/…`), art form
  (`/art-forms/…`), room, newsroom story and policy page
- `hreflang` alternates on every entry, so Google can pair `/shop` with `/hi/shop`
  instead of treating them as duplicates
- no `/admin`, no `/api`, no `/order/`, no `/cart` — private pages are excluded
  from the sitemap as well as from `robots.txt`

## Using it

**Google Search Console** (once DNS points at the server):

1. Add the property `snehavrinda.in` (Domain property needs the DNS TXT record;
   URL-prefix property needs nothing but the live site).
2. Sitemaps → enter `sitemap.xml` → Submit.
3. Expect "Success" within a day. Discovered pages appear under Pages → Indexed.

**Bing / Yandex** accept the same URL. Nothing else is needed — `robots.txt`
already carries `Sitemap: https://snehavrinda.in/sitemap.xml`, so a crawler that
reads the robots file finds it without being told.

**Do not** upload this file to Search Console. It is a copy for reading.
